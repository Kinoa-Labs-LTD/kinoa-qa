kinoa-qa plugin · 0.6.0

MCP Plan and Run

Two QA skills for stories that ship new kinoa_* MCP tools. mcp-plan writes a black-box test plan. mcp-run runs it against the deployed stand through the kinoa connector and writes the report.

/kinoa-qa:mcp-plan /kinoa-qa:mcp-run data: ~/.kinoa-qa/mcp/ source: docs/guides/mcp-skills-guide.html
How it fits together

One loop: plan, run, report, next plan

Input Jira story A story whose deliverable is new kinoa_* tools.
Skill mcp-plan Interviews you once, then writes the plan in pieces.
File Test plan ~/.kinoa-qa/mcp/plans/
<KEY>-<domain>-test-plan-v<N>.md
Skill mcp-run Calls the tools through the kinoa connector, case by case.
File Test report ~/.kinoa-qa/mcp/reports/
<KEY>-<domain>-test-report-<STAMP>.md

↺The report feeds the next plan version. Run mcp-plan again after a run, and it folds the findings, notes and plan defects into -v2, keeping the old case ids. The next mcp-run uses the newest report as its baseline.

The two skills

What each one is for

mcp-plan

writes the plan
/kinoa-qa:mcp-plan <Jira URL of the story>

Use it when an MCP story needs a test plan, or when a run has reported and the plan needs its next version ("fold the report findings into the plan").

The plan has to work in a separate chat from the file alone. It never edits the plugin: it only adds its new plan to the data folder.

mcp-run

runs it and reports
/kinoa-qa:mcp-run <KEY or plan file>

Use it for a first run, a re-run after fixes, a regression check, a partial run of named cases, Part B only, or to resume a paused run ("continue").

It runs against the deployed stand: it creates and changes real entities, and in Part B it changes your roles, then restores them.

Before you start

What you need

WhatForWhyIf it is missing
kinoa-qa plugin, 0.6.0 or newer both The skills ship in the plugin. The /kinoa-qa:mcp-* commands do not exist.
kinoa connector (the stand's MCP server, HTTP /mcp, OAuth) mcp-run Every case calls a kinoa_* tool through it. Checked at start. It says the connector is missing or not logged in, writes no report and stops.
kinoa connector mcp-plan Compares the story's tools with the stand's tools/list. The plan records not done: no connector in this chat, and the run's inventory cases check the tools instead.
bash and perl both Both skills run check-layout.sh. The layout check cannot run.

Install or update the plugin:

claude plugin marketplace add Kinoa-Labs-LTD/kinoa-qa
claude plugin install kinoa-qa@kinoa-qa

Add the kinoa connector with the claude mcp add --transport http kinoa … command from the kinoa-mcp repo's README, then log in to it through /mcp. The plugin does not add it for you.

mcp-plan, step by step

How a plan gets written

  1. Checks the source branch. If the chat can see the kinoa-mcp source, it checks it is on develop or master and not behind its remote. Otherwise it stops: only you pull or switch branches.
  2. Looks for earlier work. It creates the data folder and looks for the story's plans and reports. With a plan there, it writes the next version as a new file.
  3. Asks everything in one message. Fixed test data (there is no default), the tool names, artifact policy, delete semantics, irreversible tools, checkpoints, replicas and write mode, which roles may call which tool, and known issues.
  4. Compares tools with the stand. With the connector in the chat, it compares the story's tools with the stand's tools/list and shows you every difference.
  5. Writes the plan in pieces. CRUD, validations, role-based access, and the grey-box layer from the source last. Then it runs check-layout.sh.

Part A

Everything that needs no permission change. It runs unattended, start to finish.

Part B

Role-gated checks, grouped into checkpoints. Each one changes your roles through the admin role API, and the run restores them at the end.

mcp-run, step by step

How a run goes

  1. Start checks. It reads the rules, then looks for kinoa_* tools (e.g. kinoa_system_ping) in the session without calling one. If there are none, or if the plan's fixed data is missing, it stops before case 1 and writes no report file.
  2. Picks the plan and the baseline. The plan is the file you name, or else the highest version. The baseline is the newest report for the same story. If you did not give a run reason, it asks for one.
  3. Creates the report file before case 1, so a run can pause and resume ("continue", or the report's file name).
  4. Runs the cases. The preflight, then Part A to completion, then Part B one checkpoint at a time. Every response goes into the report at the call.
  5. Hands over. It runs check-layout.sh, then gives you the overall status, each red item, and any rule change proposals.
GREEN

At least one case ran, with no FAIL and no finding.

RED

The run saw at least one defect: a FAIL or a finding.

BLOCKED — reason

No case ran, so nothing was tested.

Where files live

The data folder

Plans and reports live outside the plugin, so a plugin update never deletes them. Both skills create the folders on first use.

WhatFolderWritten byRead by
Test plans~/.kinoa-qa/mcp/plans/mcp-planmcp-run, and mcp-plan for the next version
Test reports~/.kinoa-qa/mcp/reports/mcp-runmcp-plan, and mcp-run for the baseline

To check the plans and reports by hand (<plugin> is the plugin's install folder):

bash <plugin>/skills/mcp-plan/scripts/check-layout.sh                # ~/.kinoa-qa/mcp/
bash <plugin>/skills/mcp-plan/scripts/check-layout.sh <data folder>  # another folder with plans/ and reports/

It prints one PROBLEM line per failure, exits 1 if there is any, and exits 2 on a usage error. LEGACY, REDACTED and OLDER lines are information only.

If you used the zip copy

Moving to the plugin

Before 0.6.0 the skills were the folders mcp-qa-plan and mcp-qa-execute, in ~/.claude/skills or <kinoa-mcp checkout>/.claude/skills.

  1. Update the plugin first, so /kinoa-qa:mcp-plan and /kinoa-qa:mcp-run are there.
  2. Move your plans and reports. Here, <skills> is the folder you installed the zip copy in: 
    mkdir -p ~/.kinoa-qa/mcp/plans ~/.kinoa-qa/mcp/reports
mv <skills>/mcp-qa-plan/docs/plans/*-test-plan*.md ~/.kinoa-qa/mcp/plans/
mv <skills>/mcp-qa-execute/docs/reports/*-test-report-*.md ~/.kinoa-qa/mcp/reports/
  3. Delete only mcp-qa-plan and mcp-qa-execute. Leave every other folder in that skills folder as it is.

mcp-qa-ready is not part of this plugin. Keep it where it is. After the move it no longer finds the plans, the reports or the mcp-plan references, until it moves too.
